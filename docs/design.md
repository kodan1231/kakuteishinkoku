# 確定申告サポート 設計書（ドラフト v0.2）

> ステータス: **承認済み**（Step 0 / Step 1 着手）
> 最終更新: 2026-10-21
>
> v0.2 の主な変更: サーバー（Worker）を「招待・許可アカウントの管理」「OCR」「トークン交換の中継」だけに絞り、
> セッション・トークン・ドライブ上のファイル情報はすべて**各ユーザーの端末側**で持つ構成に変更。

---

## 1. 目的とスコープ

日常の支出を発生時点でスマホから記録し（領収書撮影＋自動読み取り）、確定申告時に必要な形式で出力できるようにする。

| フェーズ | 内容 | 目標 |
|---|---|---|
| **1** | 医療費控除（家族分含む）の記録・集計・出力 | 2026年12月中 |
| **2** | 副業（フリーランスSE・民泊等）の収入／経費記録、勘定科目別集計、白色申告（収支内訳書）向け出力 | 2027年1〜2月 |
| **3** | 減価償却、訂正削除履歴、年度比較 等 | 必要に応じて |

本書はフェーズ1の詳細設計とフェーズ2の概要を扱う。フェーズ2の詳細は着手前に別途設計する。

### 対象外（現時点）
- 青色申告（複式簿記）
- クレジットカード・銀行明細の取込
- e-Tax への直接送信（国税庁「確定申告書等作成コーナー」へのファイル読込で対応）

## 2. 基本方針・制約

| 項目 | 内容 |
|---|---|
| アプリ名 | 確定申告サポート（Worker 名: `kakuteishinkoku`、Cloudflare 上に作成済み） |
| URL | `https://kakuteishinkoku.<subdomain>.workers.dev` |
| 費用 | **すべて無料枠**で運用（クレジットカード登録が必要なサービスは使わない） |
| Cloudflare | Free プラン（既存アカウントを流用、リソースは本アプリ専用に新規作成） |
| Google Cloud | 本アプリ専用のプロジェクトを新規作成（既存アプリに影響を与えない） |
| ログイン | Google アカウントのみ |
| 利用開始 | 招待制（招待リンクを LINE 等で送付） |
| 利用端末 | 主にスマホ（PWA としてホーム画面に追加） |
| リポジトリ | 非公開 |

### 責任分界
| 主体 | 責任範囲 | 持つ情報 |
|---|---|---|
| 各ユーザー | 自分のデータ（医療費・家族・領収書）の保管 | **自分の Google ドライブ**、端末内のログイン情報 |
| 管理者 | アプリのコードの管理、誰が使えるか（招待・許可）の管理、OCR の提供 | D1 の許可アカウント・招待情報のみ |

- サーバーはユーザーのデータもトークンも**保存しない**。
- ユーザーが利用停止になってもデータは本人のドライブに残る（スプレッドシートとして閲覧できる）。
- ただしアプリのプログラムは管理者が配信しているため「技術的に絶対アクセスできない」わけではない。招待時の説明は「管理者はデータを保存しておらず、通常の運用で見ることはない」とする。

### Cloudflare Free プランで設計に効く制約
| 制約 | 値 | 設計上の対応 |
|---|---|---|
| Workers CPU 時間 | 10ms / リクエスト | 画像リサイズ・xlsx 生成などは端末側で処理。Worker は軽い処理のみ（外部 API の待ち時間は CPU 時間に含まれない） |
| Workers リクエスト数 | 100,000 / 日 | ドライブへのアクセスは端末から直接行うため、Worker へのリクエストはごく少ない |
| D1 | 500MB / DB | 許可アカウント・招待・OCR 利用回数のみのため問題なし |
| Workers AI | 10,000 Neurons / 日 | ユーザーごとに1日の OCR 回数上限を設ける。超過時は手入力 |

## 4. 認証・招待

### 4.1 ログイン方式
- Google OAuth の**認可コードフロー + PKCE**（リダイレクト方式。ポップアップは使わない）
- スコープ: `openid` `email` `profile` `https://www.googleapis.com/auth/drive.file`
  - `drive.file` は**本アプリが作成したファイルのみ**アクセス可能。Sheets API もこのスコープで操作できる
- Google の「ウェブアプリ」型クライアントはトークン交換に client secret が必要なため、**交換と更新だけ Worker が中継**する（Worker はトークンを保存しない）
- OAuth 同意画面は「本番環境」で公開する（「テスト」のままだと更新用トークンが7日で失効するため）

### 4.2 初回ログインの流れ
```
端末                              Worker                         Google
 │ PKCE verifier/state を生成          │                               │
 │──── リダイレクト（認可画面）────────────────────────────────────────────▶│
 │◀─── code 付きでアプリに戻る ─────────────────────────────────────────────│
 │ POST /api/auth/token              │                               │
 │  { code, verifier, inviteToken? }─▶│──── code を交換 ───────────────▶│
 │                                   │◀── access / refresh / id token ─│
 │                                   │ id token を検証                  │
 │                                   │ 許可リストに居る or 有効な招待あり？     │
 │                                   │  ├ No → トークンを失効させて 403     │
 │                                   │  └ Yes → （招待なら許可リストに登録）  │
 │◀── トークン一式を返す（保存はしない） ──│                               │
 │ 端末に保存                          │                               │
```

### 4.3 自動再ログイン（トークン更新）
- アクセストークン・ID トークンの有効期限は1時間
- **アプリ起動時・画面復帰時・期限の5分前**に、端末が裏で `POST /api/auth/refresh` を呼ぶ
  - Worker は許可リストを確認したうえで Google に中継し、新しいトークンを返す（保存しない）
  - ユーザーの操作は不要
- 次の場合のみ、ログイン画面に戻る
  - 6か月以上アプリを使わなかった（Google の更新用トークンの失効）
  - Google のパスワード変更、Google アカウント側でのアクセス取り消し
  - 管理者による利用停止

### 4.4 端末内のトークン保存
| 情報 | 保存場所 |
|---|---|
| 更新用トークン（refresh token） | IndexedDB。**取り出し不可（non-extractable）の WebCrypto 鍵**で AES-GCM 暗号化して保存 |
| アクセストークン・ID トークン | メモリのみ（再起動時は更新用トークンから再取得） |

- XSS 対策として CSP を厳格にし、外部スクリプトを読み込まない（接続先は自サイトと `*.googleapis.com` `accounts.google.com` `oauth2.googleapis.com` のみ）

### 4.5 Worker での本人確認
- Worker を呼ぶときは `Authorization: Bearer <Google の ID トークン>` を付ける
- Worker は ID トークンの署名（Google の公開鍵）・発行者・宛先（自アプリのクライアントID）・有効期限を検証し、D1 の許可リストと照合する
- サーバー側にセッションは持たない（ステートレス）

### 4.6 招待
```
管理者: 管理画面で招待を作成（メモ: 「山田さん」など）
     → 招待URL https://.../invite/<token> をコピーして LINE 等で送付
被招待者: URL を開く → 説明画面（データの保存先など）→ 「Google でログイン」
     → 4.2 の流れで inviteToken を添えて送信 → 許可リストに登録・招待は使用済みに
```
- 招待リンクは**1回限り・有効期限7日**（作成時に変更可）
- 招待されていない Google アカウントは、Google 認証後でもトークンを返さず拒否
- 管理者は招待の取消、ユーザーの利用停止ができる（停止すると次回のトークン更新で利用不可になる）
- **初期管理者**: Worker の環境変数 `ADMIN_EMAIL` と一致する Google アカウントは招待なしで登録され、管理者権限を持つ

## 5. データ設計

### 5.1 D1（許可アカウント・招待のみ）

```sql
-- 許可アカウント
CREATE TABLE allowed_users (
  id            TEXT PRIMARY KEY,               -- UUID
  google_sub    TEXT NOT NULL UNIQUE,           -- Google アカウント識別子
  email         TEXT NOT NULL,
  display_name  TEXT,
  role          TEXT NOT NULL DEFAULT 'user',   -- 'admin' | 'user'
  status        TEXT NOT NULL DEFAULT 'active', -- 'active' | 'disabled'
  created_at    INTEGER NOT NULL,
  last_seen_at  INTEGER
);

-- 招待
CREATE TABLE invitations (
  id          TEXT PRIMARY KEY,
  token_hash  TEXT NOT NULL UNIQUE,             -- 招待トークンの SHA-256
  memo        TEXT,                             -- 誰宛か（管理者用メモ）
  created_by  TEXT NOT NULL REFERENCES allowed_users(id),
  expires_at  INTEGER NOT NULL,
  used_at     INTEGER,
  used_by     TEXT REFERENCES allowed_users(id),
  revoked_at  INTEGER,
  created_at  INTEGER NOT NULL
);

-- OCR 利用回数（無料枠を一人で使い切らないための上限管理）
CREATE TABLE ocr_usage (
  user_id  TEXT NOT NULL REFERENCES allowed_users(id),
  date     TEXT NOT NULL,                       -- 'YYYY-MM-DD'（JST）
  count    INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, date)
);
```

**医療費・家族・トークン・ドライブのファイル情報は D1 に一切保存しない。**

### 5.2 Google ドライブのフォルダ構成（ユーザーごと）

```
マイドライブ/
└ 確定申告サポート/
   ├ 2026/
   │  ├ 台帳_2026（スプレッドシート）
   │  ├ 領収書/
   │  │  ├ 20260115_〇〇病院_12340_<id>.jpg
   │  │  └ 20260203_△△薬局_2980_<id>.pdf
   │  └ 出力/
   │     └ 医療費集計フォーム_2026_<日時>.xlsx
   └ 2027/
      └ ...
```
- ファイル名に「日付_支払先_金額」を含め、ドライブ上でも検索しやすくする
- **初回設定（`/setup`）**: アプリのフォルダが見つからない場合、何かを作る前に初回設定画面を出す
  - ドライブに保存すること（運営者のサーバーには保存しないこと）を説明し、**「同意して作成」で初めてフォルダと台帳を作成**する。同意しない場合は利用できない旨を表示しログアウトを促す
  - 本人の名前は Google アカウントの名前を初期値にした入力欄で**確認してもらってから**登録する（ニックネームなら本名に直してもらう。全角10文字以内）
  - 同意日時はルートフォルダの `appProperties.consentedAt` と台帳の `_meta.consented_at` に記録
  - 別の端末では既存のフォルダが見つかるため、初回設定は出ない
- **新しい年度の台帳**: 初回設定済みなら、選んだ年度の台帳が無いときに自動作成し、家族を前年度（無ければ最も近い年度）からコピーして、作成したことを画面に表示する
- 領収書・出力フォルダは Step 4・7 で必要になったときに作成する
- **ファイルの見つけ方**: 作成時にドライブの `appProperties`（`app=kakuteishinkoku` と `type=root` / `yearFolder` / `ledger`、`year=2026`）を付けておき、端末はこの条件で検索して見つける
  - 見つけた（作成した）ID はユーザーごとに localStorage にキャッシュし、次回は ID で直接開く（ゴミ箱に入っていないかは確認する）。ドライブの検索は作成直後のファイルをすぐ返さないことがあるため、作成直後に見失わない目的もある
  - 別の端末からログインしても同じファイルにたどり着ける（D1 に記録する必要がない）
  - 同じ年度の台帳が複数見つかったら、最初に作成されたものを使い、警告を表示する

### 5.3 台帳スプレッドシート（年度ごと）

全シート共通: 1行目はヘッダ（編集すると警告が出る保護。編集自体は止めない）、`id` 列で行を特定、削除は論理削除（`削除済` 列）。シートの並びは 医療費・家族・設定・_meta。
見出しの変更・`id` の重複・シート名の変更を検知したら画面に警告を出す（自動修復はしない）。

#### シート「_meta」（非表示）
| key | value |
|---|---|
| schema_version | 1 |
| app | kakuteishinkoku |
| year | 2026 |
| created_at | 台帳の作成日時（ISO 8601） |
| consented_at | ドライブ保存への同意日時（ISO 8601） |

#### シート「家族」
| 列 | 型 | 説明 |
|---|---|---|
| id | 文字列 | UUID |
| 氏名 | 文字列 | 医療を受けた人（集計フォームの上限に合わせ10文字以内） |
| 続柄 | 文字列 | 本人／配偶者／子／父母／その他 |
| 並び順 | 数値 | |
| 削除済 | TRUE/FALSE | |

> 家族は年をまたいで使うため、新年度の台帳作成時に前年度からコピーする。

#### シート「医療費」
| 列 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列 | ○ | UUID |
| 支払日 | 日付 | ○ | `YYYY-MM-DD` の文字列で書き込む（手入力のシリアル値・`/` 区切りも読める）。選択中の年度の日付のみ |
| 対象者ID | 文字列 | ○ | 家族シートの id |
| 対象者名 | 文字列 | ○ | 表示・出力用（記録時点の名前） |
| 支払先 | 文字列 | ○ | 病院・薬局など。集計フォームに合わせ20文字以内 |
| 区分 | 文字列 | ○ | `診療・治療` / `医薬品購入` / `介護保険サービス` / `その他の医療費` のいずれか1つ |
| 支払額 | 数値 | ○ | 円。1〜999,999,999 の整数 |
| 補填額 | 数値 | | 円（既定 0）。支払額以下 |
| 内容メモ | 文字列 | | 交通費の経路、薬の名前など（200文字以内） |
| 領収書ファイルID | 文字列 | | ドライブのファイルID（複数はカンマ区切り） |
| 読取方法 | 文字列 | | `ocr` / `manual` |
| 作成日時 | 日時 | ○ | |
| 更新日時 | 日時 | ○ | |
| 削除済 | TRUE/FALSE | ○ | |

**年度は支払日の年で決まる**（12月診療・1月支払 → 支払った年の分）。

#### シート「設定」
| key | value |
|---|---|
| 総所得金額等 | 控除見込額の計算用（任意） |

### 5.4 データアクセス方針
- すべて端末から Sheets API / Drive API を直接呼ぶ
- 一覧・検索・集計は、その年度の医療費シートを丸ごと読み込み、端末側で処理（年数百行程度なので十分速い）
- 追加は `values.append`、更新は `id` から行番号を特定して `values.update`
- 台帳が手で編集されて壊れた場合（ヘッダの欠落、id の重複など）は検知して警告を表示

## 6. 領収書の取り込み

### 6.1 画像
1. スマホでカメラ撮影 or 写真選択（**複数枚の一括選択に対応**）
2. 端末側で縮小（長辺 1600px、JPEG 品質 0.8 程度）。EXIF の位置情報は削除
3. 端末からドライブの「領収書」フォルダへ直接アップロード（フォルダは最初の添付時に作成）
4. PDF はそのままアップロード（上限 10MB）
5. 1件の記録に何枚でも添付できる。ファイル名は `20260115_〇〇病院_12340_<記録idの先頭8文字>.jpg`（2枚目以降は `-2` `-3`…）
6. 記録の日付・支払先・金額を変えたとき、添付を外したときは、ファイル名を付け直す
7. 記録を削除したとき・添付を外したときは、ファイルをドライブのゴミ箱へ移す（30日間は元に戻せる）

### 6.1a 手入力（Step 4）
- 入力項目は 5.3「医療費」のとおり。支払日の初期値は今日（選択中の年度が今年でなければ空欄）、医療を受けた人の初期値は本人
- 支払先は今年入力した支払先を候補に出し、新規入力で候補と一致したら前回の区分を自動で入れる（変更可）
- 金額は全角数字・カンマ・円記号も受け付ける
- 支払日は「月」「日」のプルダウン（iPhone ではリール）で選ぶ。年は選択中の年度で固定、「今日」ボタンあり
- **通院の交通費**: 区分「診療・治療」の入力時に「通院の交通費も記録する」をオンにすると、交通機関・出発→到着・片道運賃・往復を入力でき、保存時に**別の記録**として追加する（新規は診療と交通費を1回の書き込みで追加）
  - 交通費の記録: 支払先＝交通機関、区分＝その他の医療費、支払額＝運賃（往復なら2倍）、メモ＝`通院: 自宅→順天堂医院（往復）`。日付・医療を受けた人は診療と同じ
  - 台帳の列は増やさず、メモの `通院: ` で交通費の記録を見分け、同じ日・同じ人の交通費を診療にひも付けて表示する（2つは独立した記録で、別々に編集・削除できる）
- **前回の呼び出し**: 新規入力画面に最近の支払先（最大5件）のボタンを出し、押すと前回の支払先・区分・医療を受けた人と、ひも付いた交通費の内容を入れる（支払額は空欄）。編集画面の「この内容で新しく記録」も同じ
- 領収書は記録の編集画面の「保存」で端末に保存できる（スマホは共有メニュー、PC はダウンロード）

### 6.2 写真からの読み取り（OCR）
- **Cloudflare Workers AI の画像対応モデル**を使用（無料枠内）
  - 候補: Llama 4 Scout、Gemma 3 / Gemma 4、Mistral Small 3.1、Llama 3.2 Vision、Kimi K2.6、Qwen 3.8 → **Step 0 で実際の領収書を使って精度を比較して決定**（検証ページ `/lab/ocr`）
- 端末で OCR 用の小さい画像（長辺 1024px 程度）を作り、`POST /api/ocr` に送る
  - Worker は画像を保存せず、読み取り結果だけを返す
- モデルへの指示: 領収書から `支払日` `支払先` `金額（合計）` `区分の推定` を JSON で返させる
- 読み取り結果は**必ず確認・修正画面を経てから保存**
- 1人あたり1日の上限回数を設ける（初期値 30 回、Step 0 の消費量から調整）。上限超過・失敗時は手入力
- PDF は OCR 対象外（フェーズ1）。手入力とする

### 6.3 一括登録の流れ
```
写真を複数選択 → 順にアップロード＆OCR（裏で実行）
            → 確認待ちリストに並ぶ → 1件ずつ確認・修正して保存
```
手元にある2026年1〜10月分の領収書をまとめて登録するための機能。確認待ちの状態は端末内（IndexedDB）に保持する。

## 7. 集計・出力

### 7.1 集計画面
- 年間の支払額合計・補填額合計・対象者別・区分別・月別の小計
- **控除見込額** = 支払額合計 − 補填額合計 − min(10万円, 総所得金額等 × 5%)（上限200万円）
  - 総所得金額等は設定画面で入力（会社員は源泉徴収票の「給与所得控除後の金額」が目安）。未入力なら10万円で計算
- セルフメディケーション税制とは併用できない旨を注意書きとして表示

### 7.2 医療費集計フォーム出力
- 国税庁配布の**「医療費集計フォーム」(xlsx) に記録を流し込んだファイル**を端末側で生成
  - 公式テンプレートをアプリに同梱し、ExcelJS で値を書き込む
  - 生成したファイルはダウンロードし、ドライブの「出力」フォルダにも保存
- 確定申告書等作成コーナーの医療費控除画面で「医療費集計フォームを読み込む」から取り込む
- **フォームの列構成・入力規則・件数上限は、最新の公式ファイルで Step 0 に確認してから実装する**（改版に備えてテンプレートを差し替えやすくする）
- 確認結果（2026-10-22、令和7年分ページで配布の `iryouhi_form_v3.1.xlsx`、Ver.3.1。前年の Ver.3.1 も引き続き利用可）
  - シート「医療費集計フォーム」の **9〜1003 行目（995 件）** に入力。A 列 No は数式 `ROW()-8`、C3/C4 は合計の数式
  - ブックは構造保護（シートの追加・削除不可）。2 枚目は「ご利用に当たって」

  | 列 | 項目 | 入力規則 | 台帳からの対応 |
  |---|---|---|---|
  | B | 医療を受けた人 | 文字数 0〜10（全角10文字以内） | 対象者名 |
  | C | 病院・薬局などの名称 | 文字数 0〜20（全角20文字以内） | 支払先 |
  | D | 診療・治療 | リスト「該当する」（空欄＝非該当） | 区分 |
  | E | 医薬品購入 | 同上 | 区分 |
  | F | 介護保険サービス | 同上 | 区分 |
  | G | その他の医療費 | 同上 | 区分 |
  | H | 支払った医療費の金額 | 整数 0〜999,999,999 | 支払額 |
  | I | 左のうち、補填される金額 | 整数 0〜999,999,999 | 補填額 |
  | J | 支払年月日 | 任意。セル書式は文字列（`@`） | 支払日 |

  - 公式の入力方法は「領収書1件ずつ」または「医療を受けた人・病院ごとにまとめて」のどちらでもよい
  - 補填額は給付の目的となった医療費を限度に差し引き、他の医療費からは差し引かない（注意書き）
  - セルフメディケーション税制の適用者は利用不可
- 予備として CSV 出力も用意

## 9. Worker API 一覧（フェーズ1）

ドライブ・スプレッドシートへのアクセスは端末から Google API を直接呼ぶため、Worker の API は以下のみ。

| メソッド | パス | 認証 | 概要 |
|---|---|---|---|
| POST | `/api/auth/token` | なし（code で検証） | 認可コードをトークンに交換（中継）。許可リスト・招待を確認 |
| POST | `/api/auth/refresh` | なし（refresh token で検証） | トークン更新（中継）。許可リストを確認 |
| POST | `/api/auth/revoke` | ID トークン | ログアウト時に Google 側のトークンを失効 |
| GET | `/api/me` | ID トークン | 自分の権限（admin/user）を返す |
| GET | `/api/invites/:token` | なし | 招待の有効性確認 |
| POST | `/api/ocr` | ID トークン | 画像を読み取って候補値を返す（画像は保存しない） |
| GET/POST/DELETE | `/api/admin/invites` | ID トークン（admin） | 招待の一覧／作成／取消 |
| GET/PATCH | `/api/admin/users` | ID トークン（admin） | ユーザー一覧／利用停止・再開 |

## 10. セキュリティ・プライバシー

| 項目 | 対応 |
|---|---|
| データの保存場所 | 各ユーザーの Google ドライブのみ。サーバーには保存しない |
| Google の権限 | `drive.file` のみ（ユーザーの他のファイルにはアクセスできない） |
| トークン | 端末内のみに保存（更新用トークンは取り出し不可の鍵で暗号化）。Worker は中継のみで保存しない |
| サーバーの本人確認 | Google の ID トークンを毎回検証（ステートレス） |
| 招待トークン | ハッシュのみを D1 に保存 |
| 位置情報 | 画像の EXIF はアップロード前に削除 |
| OCR | 画像は Worker・D1 に保存しない。Workers AI に送られた画像はモデルの学習には使われない（Cloudflare の規約） |
| XSS | 厳格な CSP、外部スクリプトを読み込まない |
| 秘密情報 | `GOOGLE_CLIENT_SECRET` は `wrangler secret` で設定し、リポジトリには置かない |
